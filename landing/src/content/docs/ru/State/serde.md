Библиотека хранит всё, что донесёт serde, — а значит, тип для хранения написан
сразу на двух языках. Эта страница про то, где они встречаются: какие
serde-атрибуты библиотека читает как свои, какие отвергает и в какие не лезет
вовсе.

Развилка, из которой растёт всё остальное, — не «какой атрибут», а «на чём он
стоит».

**Структура, чьи поля — пути** (с `#[amethystate]` или встроенная через
`nested`) целиком через serde не проходит никогда. Её поля лежат по одному,
каждое по своему пути, а сама она не кодируется нигде. Поэтому атрибут здесь
читается как высказывание о путях — или отвергается.

**Лист** — всё, что лежит одним значением по одному пути, — наоборот. Store
отдаёт его кодеку целиком, забирает байты и внутрь не смотрит.

## На структуре, чьи поля — пути

### Где лежит поле

`rename` называет место, где поле лежит, а `rename_all` на структуре говорит это
один раз за все поля. Точка в имени — уровень, так что поле можно не только
переименовать, но и опустить куда угодно под префикс:

<!-- shown: a struct that says where its fields go -->
```rust
#[amethystate(prefix = "net")]
#[serde(rename_all = "camelCase")]
pub struct NetState {
    #[amestate(default = 8080u16)]
    pub listen_port: u16,

    #[serde(rename = "tls.enabled")]
    #[amestate(default = false)]
    pub tls: bool,
}
```
<!-- /shown -->

Получается `net.listenPort` и `net.tls.enabled`.

На точке стоит задержаться. Для serde `"tls.enabled"` было бы одним именем, в
котором случилась точка; здесь это два уровня. Двусмысленности нет — структура
до serde и не доходит, — но тот, кто читает атрибут, держа в голове только
serde, прочтёт его иначе.

### Поле, чьи пути лежат на уровне хозяина

`flatten` на `nested`-поле говорит: его поля лежат здесь, без сегмента с его
именем.

<!-- shown: a nested struct whose fields sit at their holder's level -->
```rust
#[amethystate(prefix = "editor")]
pub struct Editor {
    #[serde(flatten)]
    #[amestate(nested)]
    pub window: Window,
}
```
<!-- /shown -->

Получается `editor.width`, а не `editor.window.width`.

Два флэттенутых ребёнка, у которых поле названо одинаково, — ошибка компиляции с
обоими именами: каждый кладёт свои поля на этот уровень, и они писали бы друг
поверх друга. То же и для ребёнка, чьё поле названо так же, как поле рядом.

**Flatten двигает пути, поэтому дописать его к тому, что уже выпущено, —
миграция.** Данные остаются там, куда их положила старая сборка, новая читает
уровнем выше, а человек видит, что настройки сбросились. Так же с `rename` и с
`rename_all`, который делает это со всеми полями разом.

### Чем поле заполнить, когда его нет

`#[serde(default)]` и `#[serde(default = "some_fn")]` читаются как
`#[amestate(default = ..)]`: и то и другое — значение на случай отсутствия.
Написать оба — ошибка компиляции с обоими именами: они могут разойтись, и никто
не скажет, чьё взяло.

`amestate` берёт выражение (expression) там, где serde берёт путь к функции, —
только ради этого он и остался:

```rust
#[amestate(default = 8080)]
pub port: u16,
```

говорит то, для чего serde нужна `fn default_port() -> u16 { 8080 }`.

Написанный на структуре, а не на поле, `#[serde(default)]` отвергается. Он
заполняет то, что одно закодированное значение опустило, — из одного `Default`
на всю структуру. Здесь нет закодированного значения, из которого что-то можно
опустить: каждое поле есть или нет само по себе, поэтому и значение на случай
отсутствия пишется на каждом.

### Поле, которое лежит иначе

`serialize_with`, `deserialize_with` и `with` — ответ serde на тип, чья
собственная кодировка не та, которую вы хотите видеть на диске. Serde зовёт их
изнутри структуры, держащей поле, а эта структура не кодируется никогда — так
что то же самое говорится этому макросу, и теми же функциями:

```rust
#[amestate(with = since_the_epoch)]
pub opened: SystemTime,
```

`with = m` — это `m::serialize` и `m::deserialize`; любую половину можно назвать
отдельно, как `serialize_with` или `deserialize_with`. Напишете одну — вторая
останется от типа, и значение будет записано одним способом, а прочитано другим.
Пишите обе, если не имеете в виду ровно это.

Между значением и путём нет ничего, кроме пары: на пути лежит то, что вывела
пишущая половина, и читает это только читающая. Поэтому типу не нужна
собственная кодировка, и листом может быть тип из чужого крейта.

### Что отвергается

Каждое — ошибка компиляции там, где написано, и в ней сказано, чем это пишется
вместо.

| написано | почему нет и что вместо |
| --- | --- |
| `deny_unknown_fields` | описывает одно закодированное значение, а его нет. Путь, который никто не объявлял, — не ключ внутри чего-то; за поле отвечает `on_unreadable` |
| `tag`, `tag` + `content`, `untagged` | говорят, как вариант называет себя внутри одного значения, а значения нет |
| `transparent` | заставляет структуру кодироваться своим единственным полем, а эта не кодируется никак |
| `from`, `into`, `try_from` | превращают структуру целиком по дороге через serde, а целиком она туда не попадает. Превращение одного значения живёт на типе того поля |
| `remote` | пишет serde-реализации для чужого типа, а этот ваш |
| `skip`, `skip_serializing`, `skip_deserializing` | просят не включать поле в значение, которого нет. Полю здесь доступен `#[amestate(volatile)]` — и он говорит больше: ни пути, ни записи в схеме, ни того, что понесёт миграция |
| `skip_serializing_if` | означал бы, что путь не пишут, — а значит, лежавшее по нему осталось бы, и сброс поля в то самое значение, что названо в правиле, его не стёр бы |
| `alias` | называет второе написание для чтения, а путь ищут под одним именем. Шаг `#[migrate]` с `#[rename(old => new)]` переносит данные один раз при открытии и на том заканчивает |
| `getter` | читает через функцию — так serde поступает с типом, которым не владеет |
| `borrow` | заимствует из входа, а значение приходит от движка владеемым, по одному пути за раз |
| `serialize_with`, `deserialize_with`, `with` | serde зовёт их изнутри структуры, держащей поле, а эта не кодируется никогда. То же самое говорится этому макросу: `#[amestate(with = ..)]` или одна его половина, теми же функциями |
| `default` на структуре | заполняет то, что опустило одно закодированное значение, а его нет. Каждое поле отсутствует само по себе, поэтому и пишется на поле |
| `crate` | указывает, где лежит сам serde, — это нужно крейту, который его переэкспортирует. Для этой структуры serde не пишет ничего, так что и указывать не на что |

Атрибуты разбирает собственный парсер serde, поэтому то, что serde сам считает
противоречием, возвращается его же словами.

## Внутри листа

Ничего из написанного выше здесь не действует. Store кладёт значение целиком по
одному пути и читает его обратно, а что ему сказали по дороге — дело ваше и
serde:

<!-- shown: a leaf, where serde answers to nobody here -->
```rust
#[derive(Serialize, Deserialize, Default, Clone, Debug, PartialEq, AmeType)]
#[serde(rename_all = "kebab-case", deny_unknown_fields)]
pub struct Endpoint {
    pub host_name: String,

    #[serde(default)]
    pub port: u16,
}

#[amethystate(prefix = "svc")]
pub struct Service {
    #[amestate(default = Endpoint { host_name: "localhost".to_string(), port: 443 })]
    pub upstream: Endpoint,
}
```
<!-- /shown -->

`Endpoint` ложится целиком в `svc.upstream` — в kebab-case и строгим к
неизвестным полям, — и у store на этот счёт мнения нет.

Две вещи всё же чего-то стоят, и стоит знать, каких:

**Переименование внутри листа — миграция, которой здесь никто не заметит.**
Байты переехали, имя в Rust нет. В store, записанном старой сборкой, внутри
значения лежит старое имя поля, и новая сборка его не найдёт.

**`deny_unknown_fields` превращает каждое поле, добавленное позже, в жёсткий
отказ чтения для старой сборки.** proto3 выбрасывал неизвестные поля в первом
релизе и передумал в 3.5.0 ровно поэтому. Значение ваше, и решение ваше.

И две привычки, которые стоит держать — по той же причине, по какой их держит
любой формат:

**`#[serde(default)]` на каждом поле, добавленном после первого релиза.** Serde
и так пропускает поле, которого не знает, поэтому значение, записанное новой
сборкой, читается старой даром. В обратную сторону даром не выходит: полю,
которому нечем заполниться, нечего и подставить — оно валит всё значение целиком,
и лист, записанный до появления поля, перестаёт читаться.

**Именованные поля, а не кортеж.** Кортежная структура сериализуется по
позициям, так что поле, вставленное в середину, молча сдвигает все следующие.

## Что формат вообще донесёт — другой список

Ничего из этого не про то, что движок способен удержать. Это измерено и лежит в
[Ограничениях](/amethystate/ru/limitations/): ron не понесёт enum, json и sqlite
не понесут `NaN`, у toml нет места дальше `i64`. Там отказывают *значению*, а
эта страница — про *тип*, который говорит то, чего store не может записать.

Тип может пройти один список и не пройти другой.
